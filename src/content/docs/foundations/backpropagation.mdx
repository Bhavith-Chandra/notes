<Abstract>
Backpropagation is the chain rule applied in a specific order. That order is the
entire contribution: computing derivatives from the output backwards costs about
the same as one forward pass regardless of how many parameters there are, while
the forward direction would cost one pass *per parameter*. The price is memory —
you must keep every intermediate activation — and that trade determines almost
everything about how large models are trained.
</Abstract>

<KeyPoints>

- **Reverse mode is chosen because networks have one output and many inputs.** For $f: \mathbb{R}^n \to \mathbb{R}$, reverse mode gets the whole gradient in one backward sweep; forward mode needs $n$ sweeps. With $n$ in the billions this is not a constant-factor difference.
- **The cost is memory, not compute.** Every activation on the forward path must be retained for the backward pass. This is why activation memory, not parameter count, usually sets your maximum batch size.
- **Vanishing and exploding gradients are the same phenomenon.** Gradients are products of Jacobians along the path; products of many terms either shrink or grow geometrically. Residual connections fix it by making one term of each product exactly the identity.
- **Autodiff is neither symbolic nor numerical.** It evaluates exact derivatives numerically by composing known local derivatives — no expression swell, no finite-difference error.

</KeyPoints>

## Blame assignment

A network makes a prediction and it is wrong by some amount. Millions of
parameters contributed. Which ones, and how much should each move?

The naive approach: nudge one parameter, re-run the whole network, see how the
error changed. That is one full forward pass per parameter. For a billion
parameters, a billion forward passes per training step. Completely impossible.

Backpropagation gets **every** parameter's contribution in a single backward sweep
costing roughly what one forward pass costs. That is the whole idea, and it is
worth pausing on how large the saving is: a factor of a billion.

## How the trick works

Blame flows backwards through the network in the reverse of how the signal flowed
forwards.

Start at the output: *"the answer was 0.3 too high."* The final layer knows what it
did to produce that output, so it can compute two things — how its own weights
should change, and how much of the blame belongs to its *inputs*, which were the
previous layer's outputs.

Hand that blame back one layer. Repeat. Each layer needs only local information:
what it received, what it produced, and how much blame arrived from ahead.

**The saving comes from sharing.** Every path from a parameter to the output goes
through the layers ahead of it. Computing blame backwards means each shared segment
is computed once and reused by everything behind it, rather than recomputed for
every parameter.

<Aside type="tip" title="Why backwards rather than forwards">
You could apply the chain rule from inputs to output instead — that is forward-mode
autodiff — and for a function with one input and many outputs it is the better
choice. Neural networks are the opposite shape: billions of inputs (parameters),
one output (the loss). **Match the direction to the shape**, and for a scalar loss
that means backwards.
</Aside>

## The bill: memory

The backward pass needs to know what each layer saw on the way forward. So every
intermediate activation must be **kept** from the forward pass until the backward
pass reaches it.

For a large model with long sequences this dominates memory — often exceeding the
parameters and optimizer state combined. It is why you run out of memory when you
increase batch size or sequence length, and why gradient checkpointing exists.

## Two rules, and the whole algorithm

<Steps>

1. **Chain rule along a path.** If $L$ depends on $b$ which depends on $a$, then
   $\dfrac{\partial L}{\partial a} = \dfrac{\partial L}{\partial b}\cdot
   \dfrac{\partial b}{\partial a}$.

2. **Sum over paths.** If $a$ influences $L$ through several routes, add the
   contributions. This is what makes residual connections and multi-head attention
   work correctly without special handling.

</Steps>

Everything else is bookkeeping: build the graph during the forward pass, walk it in
reverse topological order, and at each node apply the local derivative.

## Gradient checkpointing

The memory/compute dial. Instead of keeping every activation, keep only every
$\sqrt{n}$-th one — the *checkpoints* — and recompute the rest during the backward
pass from the nearest checkpoint.

Memory drops from $O(n)$ to $O(\sqrt{n})$ at the cost of roughly one extra forward
pass, so about 33% more compute for a large memory saving. Standard practice for
training anything that does not fit otherwise.

## Vanishing and exploding gradients

The gradient reaching layer $k$ from a network of depth $n$ is a **product** of
$n - k$ Jacobians. Products of many terms behave badly:

- Typical magnitude below 1 → the product shrinks geometrically → early layers get
  almost no signal.
- Typical magnitude above 1 → the product grows geometrically → updates explode and
  training diverges.

These are not two problems. They are the same product behaving in the two ways a
product can.

**Residual connections are the fix that mattered.** Writing $y = x + F(x)$ makes
the Jacobian $I + \partial F/\partial x$. The identity term means the product
contains a 1 at every layer, so there is always a path along which gradient reaches
the input undiminished. This is why networks went from tens of layers to hundreds
in one paper.

## Reverse-mode autodiff

Let the computation be a DAG of primitive operations producing intermediates
$v_1, \dots, v_n$ with $v_n = L$ scalar. Define the **adjoint**

$$
\bar v_i \;\equiv\; \frac{\partial L}{\partial v_i}.
$$

Initialise $\bar v_n = 1$ and sweep in reverse topological order, accumulating over
every consumer $j$ of node $i$:

$$
\bar v_i = \sum_{j \in \operatorname{children}(i)} \bar v_j \, \frac{\partial v_j}{\partial v_i}.
$$

The sum is rule 2 above; the product inside is rule 1. **Backpropagation is this
recursion specialised to a layered network** — there is nothing else in it.

## Why it costs what it costs

The **cheap gradient principle**: for $f: \mathbb{R}^n \to \mathbb{R}^m$,

$$
\text{forward mode} \sim O(n) \cdot \operatorname{cost}(f), \qquad
\text{reverse mode} \sim O(m) \cdot \operatorname{cost}(f).
$$

Forward mode propagates one *input* direction per sweep, giving one column of the
Jacobian. Reverse mode propagates one *output* direction, giving one row.

For a loss, $m = 1$. So reverse mode delivers the entire gradient in $O(1)$ sweeps
regardless of $n$. Baydin et al. give the standard bound: the backward pass costs
at most a small constant (usually cited as ≤ 4, in practice ≈ 2) times the forward
pass.

The memory bound is the other side:

$$
\text{memory} = O\big(\text{number of intermediates on the forward path}\big),
$$

because reverse mode cannot begin until the forward pass has finished, so every
intermediate must survive in between. Forward mode has no such requirement — it
needs $O(1)$ extra memory — which is the real reason the two modes trade off rather
than one dominating.

## Layer derivatives

For a linear layer $y = Wx + b$ with incoming adjoint $\bar y$:

$$
\bar W = \bar y\, x^{\top}, \qquad \bar b = \bar y, \qquad \bar x = W^{\top}\bar y .
$$

Three things worth reading off:

- $\bar W$ is an **outer product**, so its cost matches the forward matmul.
- $\bar x$ uses $W^{\top}$ — the same weights transposed. This is why the backward
  pass is often described as running the network "in reverse".
- **$x$ must have been stored.** That single requirement is the source of the
  entire activation-memory problem.

For an elementwise nonlinearity $y = \sigma(x)$:

$$
\bar x = \bar y \odot \sigma'(x).
$$

ReLU's derivative is $\mathbb{1}\{x > 0\}$ — exactly 0 or 1. A sigmoid's peaks at
0.25, so ten sigmoid layers multiply gradient by at most $0.25^{10} \approx
10^{-6}$. **This is the vanishing-gradient problem in one line**, and it is why
ReLU replaced sigmoid.

## Products of Jacobians

For a depth-$n$ network,

$$
\frac{\partial L}{\partial x_k} = \frac{\partial L}{\partial x_n} \prod_{i=k}^{n-1} J_i, \qquad J_i = \frac{\partial x_{i+1}}{\partial x_i}.
$$

Bounding by spectral norms:

$$
\left\|\frac{\partial L}{\partial x_k}\right\| \;\leq\; \left\|\frac{\partial L}{\partial x_n}\right\| \prod_{i=k}^{n-1}\|J_i\| .
$$

If $\|J_i\| \leq \gamma$ for all $i$, the bound is $\gamma^{\,n-k}$:

- $\gamma < 1$: vanishes geometrically.
- $\gamma > 1$: explodes geometrically.
- $\gamma = 1$: preserved — and this knife-edge is exactly what normalisation and
  careful initialisation are trying to hold.

**Residual connections.** With $x_{i+1} = x_i + F_i(x_i)$,

$$
J_i = I + \frac{\partial F_i}{\partial x_i} \implies \prod_{i=k}^{n-1} J_i = \prod_{i=k}^{n-1}\left(I + \frac{\partial F_i}{\partial x_i}\right).
$$

Expanding the product gives $I$ plus terms involving the $\partial F_i$. The
leading $I$ is a path of length zero from $x_k$ to the loss — gradient reaches
every layer *undiminished* along it, no matter the depth. The network is, in this
sense, an ensemble of paths of many lengths, and the short ones carry the gradient.

## Gradient clipping

Since exploding gradients come from the product's magnitude, bound it directly:

$$
g \leftarrow g \cdot \min\left(1, \frac{c}{\|g\|_2}\right).
$$

Pascanu et al.'s justification is geometric: loss surfaces contain **cliffs** —
regions of sharp curvature where the gradient's magnitude is enormous but its
direction remains informative. Clipping preserves direction and bounds step size,
so you step off the cliff carefully rather than being thrown across the landscape.

This is why global-norm clipping is correct and per-parameter value clipping is
not: the latter changes the direction, discarding the one thing the gradient still
had right.

## Checkpointing, formally

With $n$ layers and checkpoints every $k$:

$$
\text{memory} = O\!\left(\frac{n}{k} + k\right),
$$

storing $n/k$ checkpoints plus the $k$ activations of the segment being recomputed.
Minimising over $k$:

$$
\frac{d}{dk}\left(\frac{n}{k} + k\right) = -\frac{n}{k^2} + 1 = 0 \implies k = \sqrt{n},
$$

giving $O(\sqrt{n})$ memory for one extra forward pass — the Chen et al. result.

## Where this stands, as of 2026

**Backpropagation is not the bottleneck and never really was.** The algorithm has
been stable since 1986. What changed is the systems engineering around it:
mixed-precision training, fused kernels, activation checkpointing, and sharded
optimizer state.

**Memory is the constraint that shapes distributed training.** ZeRO-style sharding
partitions optimizer state, gradients, and parameters across devices precisely
because backprop's memory footprint is what limits scale. Tensor and pipeline
parallelism are both, at bottom, strategies for fitting the backward pass.

**Biological plausibility remains an open question with no practical stakes.**
Backprop requires symmetric weights for the backward pass and a global error signal,
neither of which brains appear to have. Alternatives — feedback alignment, target
propagation, forward-forward — are interesting scientifically and none is
competitive at scale.

**Higher-order information is being revisited.** Hessian-vector products via
double-backward are cheap enough to be practical, which is what makes the
matrix-preconditioner optimizers on the [optimization
page](/training/optimization/) feasible.

## Open problems

- **The memory wall is not solved, only managed.** Checkpointing, offloading and
  sharding all trade compute or bandwidth for memory. None removes the underlying
  requirement that forward activations survive until the backward pass.

- **Sequential dependency limits parallelism.** The backward pass cannot start
  until the forward pass ends, and gradients must flow layer by layer. Pipeline
  parallelism hides this with micro-batches and cannot eliminate it.

- **No credible alternative learning rule.** Every proposed replacement is either
  much less sample-efficient or has not been demonstrated at scale.

- **Gradient noise is poorly characterised.** SGD's stochasticity is essential to
  generalisation and there is no good theory of the noise distribution or of what
  it does — which is the same gap that appears on the
  [generalization page](/foundations/generalization/).
