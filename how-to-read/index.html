How to read a page

Every topic page in this atlas has the same four-tier spine. The tiers are cumulative: each one assumes you have read the ones above it, and nothing else.

The four tiers

Section titled “The four tiers”
Tier 1 · Intuition

Plain language. No equations, no prerequisites.

No equations, no jargon, no prerequisites. Analogy and motivation only. If you have never heard the term before, everything you need to hold a conversation about it is here. Roughly 500–800 words.

Tier 2 · Mechanics

How it actually works. Pseudocode, no heavy maths.

How the thing actually works — the components, the data flow, the algorithm in steps or pseudocode. Some notation, but no derivations. This is where most readers should stop if they want working knowledge rather than research knowledge. Roughly 1,000–1,500 words.

Tier 3 · Formal

The objective, the equations, the guarantees.

The objective functions, the derivations that matter, the bounds and the assumptions they rest on. Assumes comfort with linear algebra, probability, and standard ML notation. Roughly 800–1,500 words.

Tier 4 · Frontier

Open problems, current results, and what is still contested.

Current results with real numbers, open problems, and disagreements in the literature. Assumes you have read at least the abstracts of the primary sources. This tier ages fastest — date your claims.

Stopping early is the point

Tier 1 alone should leave you with a correct mental model, not a misleading simplification. If a Tier 1 section only makes sense once you have read Tier 3, the Tier 1 section is badly written and should be fixed.

Authoring rules

Section titled “Authoring rules”

These exist so pages stay comparable to each other.

  1. One concept per page. If a page needs two abstracts, it is two pages.
  2. Never skip a tier. A page that jumps from intuition to formal is missing its most-read section.
  3. The abstract must stand alone. Assume most visitors read only the abstract and the key-points box.
  4. Bold the lead-in of every key point and every figure caption. This is the Nerfies convention and it is load-bearing for scannability.
  5. Cite in frontmatter, not inline. Papers go in the papers: array and are rendered by <Papers /> at the bottom. This keeps citations as structured data.
  6. Date frontier claims. Write “as of 2026” explicitly. Tier 4 is a snapshot, not a fact.
  7. State disagreements as disagreements. If the literature is split, say so and give the strongest form of each side. Do not resolve it by omission.

Ordering rules

Section titled “Ordering rules”

The sidebar is a curriculum, not a table of contents. Four invariants keep it that way, and npm run check:order fails the build on any violation:

  1. Every page has a numeric sidebar.order.

  2. No two pages in a directory share an order. Starlight breaks ties by filename, which produces an arbitrary reading order that looks intentional.

  3. Every index.mdx is order 0.

  4. No page lists a prereq from a later sidebar group. A forward prerequisite means the group order is wrong, not the page — fix the order, or move the page. This is why AI Safety lives under Training rather than Foundations, and why Embeddings sits after Architectures.

Place a new page by asking what the reader must already know, not by what it is about. The check will tell you if you got it wrong.

Adding a new section to the sidebar

Section titled “Adding a new section to the sidebar”

Create the directory under src/content/docs/, then:

  1. Add a group to the sidebar array in astro.config.mjs with autogenerate: { directory: '<name>' }, positioned so nothing in it depends on a group below it.

  2. Add the directory name to GROUP_ORDER in scripts/check-order.mjs, in the same position. The check compares against this list, so the two must agree.

  3. Add the section to /curriculum/ and to the card grid on the home page.

  4. Run npm run check — order, MDX lint and contrast in one command.

Moving an existing page means its URL changes. Add the old path to redirects in astro.config.mjs rather than breaking the link.
