Reinforcement Learning

Supervised learning is told the right answer. Reinforcement learning is told only whether things went well, possibly much later, and must work out which of its thousands of decisions deserve the credit. That is the credit assignment problem, and everything expensive about RL — the sample inefficiency, the instability, the sensitivity to seeds — follows from it.

What you should walk away with

  • The label problem is the whole problem. No action is ever labelled correct. The agent must infer which decisions mattered from a delayed, scalar, noisy signal — and it must generate its own data while doing so.
  • Two families: learn values, or learn a policy. Value methods estimate how good each state or action is and act greedily. Policy methods adjust action probabilities directly. Actor-critic uses both, and almost everything that works in practice is actor-critic.
  • The deadly triad predicts divergence. Function approximation, bootstrapping, and off-policy data are each fine alone. All three together can diverge, and deep RL uses all three — which is why target networks and replay buffers exist.
  • RL’s data distribution moves as the policy improves. Supervised learning has a fixed dataset; RL’s changes underneath it. This non-stationarity is why RL results are so seed-sensitive and why reported numbers need many runs to mean anything.
Tier 1 · Intuition

Plain language. No equations, no prerequisites.

Learning without being told

Section titled “Learning without being told”

Train an image classifier and every example comes with the answer. The gradient points directly at “you should have said cat”.

Now train something to play chess. After sixty moves you lose. Which move was wrong? Move 23 was probably fine. Move 41 might have been the mistake, or it might have been forced by a subtle weakness created at move 12. Nobody tells you.

That is credit assignment, and it makes RL a fundamentally harder problem than supervised learning — not just quantitatively but structurally.

The three complications

Section titled “The three complications”

  1. Delayed reward. Consequences arrive long after the decisions that caused them. The signal must be propagated backwards through time.

  2. Exploration. You only learn about actions you take. An action you never try stays unknown forever — so the agent must deliberately do things it believes are suboptimal, on the chance it is wrong.

  3. Non-stationary data. In supervised learning the dataset is fixed. In RL, the agent generates its own data, so improving the policy changes the distribution it learns from. You are fitting a moving target with data you are also moving.

Point 3 is the one people underrate. It means RL has no clean separation between “collect data” and “fit model” — the two are coupled, and instability in one feeds the other.

Two ways to decide

Section titled “Two ways to decide”

Learn the values. Estimate, for every situation, how good each available action is in the long run. Then act greedily: take the highest-valued action. The policy is implicit in the value function.

Learn the policy. Directly parameterise “what should I do here?” as a probability distribution, and shift probability mass toward actions that turned out well. No value function needed.

Each has a characteristic weakness. Value methods struggle with continuous action spaces — you cannot enumerate infinitely many actions to take a max. Policy methods have high-variance gradients, because a single trajectory’s total return is a very noisy estimate of any individual action’s quality.

Actor-critic combines them: a policy (actor) that acts, and a value function (critic) that reduces the variance of the policy’s learning signal. Essentially every practical modern method is in this family.

Why RL needs so much data

A supervised example teaches you the answer to one question. An RL episode teaches you that some sequence of many decisions produced some scalar. The information per sample is vastly lower, and it must be untangled from confounding decisions. This is why RL agents need millions of environment steps for tasks a human learns in minutes.

Tier 2 · Mechanics

How it actually works. Pseudocode, no heavy maths.

The setup

Section titled “The setup”

An MDP is (S,A,P,R,γ)(\mathcal{S}, \mathcal{A}, P, R, \gamma)(S,A,P,R,γ): states, actions, transition dynamics, reward, and a discount factor. The agent maximises expected discounted return.

The discount γ\gammaγ does two jobs. It expresses a preference for sooner rewards, and it makes the infinite sum converge. Values near 1 mean far-sighted and high-variance; near 0 means myopic and stable. It is a hyperparameter and an unusually consequential one — it defines the effective planning horizon, approximately 1/(1−γ)1/(1-\gamma)1/(1−γ) steps.

The algorithm families

Section titled “The algorithm families”
  • Q-learning / DQN
  • Policy gradient
  • TRPO and PPO
  • SAC

Learn Q(s,a)Q(s,a)Q(s,a) — the expected return from taking aaa in sss and then acting well. Act greedily with respect to it.

DQN made this work with neural networks via two additions, and both address the same underlying instability:

  • Replay buffer. Store transitions and sample randomly. Consecutive states are highly correlated, which violates the i.i.d. assumption gradient descent needs. Random sampling breaks the correlation.
  • Target network. A periodically-frozen copy used to compute the regression target. Without it, you regress toward a target that moves every time you update — the network chases itself.

Rainbow combined six independent improvements (double Q, prioritised replay, duelling architecture, multi-step returns, distributional RL, noisy nets) and showed they are largely complementary. Its ablations are the most useful thing in the paper.

Limit: the max⁡a\max_amaxa​ requires enumerable actions. Continuous control needs a different approach.

Directly parameterise πθ(a∣s)\pi_\theta(a\mid s)πθ​(a∣s) and push up the probability of actions that led to high return.

The raw estimator (REINFORCE) is unbiased and has enormous variance — it scales the gradient by the whole trajectory’s return, which includes the effects of every other decision. Two standard fixes:

  • Baseline subtraction. Subtract a state-dependent value V(s)V(s)V(s) from the return. This leaves the estimator unbiased (the baseline does not depend on the action) and substantially reduces variance.
  • Advantage estimation. Use A(s,a)=Q(s,a)−V(s)A(s,a) = Q(s,a) - V(s)A(s,a)=Q(s,a)−V(s) — how much better than average this action was. GAE interpolates between low-bias/high-variance and high-bias/low-variance estimates with a single parameter λ\lambdaλ.

The problem policy-gradient methods hit: a step that is too large can collapse the policy, and because the agent generates its own data, a collapsed policy collects bad data and may never recover. Unlike supervised learning, there is no fixed dataset to fall back on.

TRPO constrains each update to a trust region — a bounded KL divergence from the previous policy — and solves the constrained problem with conjugate gradients. Principled, and complicated to implement.

PPO achieves a similar effect with a clipped objective that is a few lines of code. It gives up TRPO’s guarantee and is overwhelmingly the more used method, including for RLHF.

Maximum-entropy RL: maximise return plus the entropy of the policy.

J(π)=E[∑trt+α H(π(⋅∣st))]J(\pi) = \mathbb{E}\left[\sum_t r_t + \alpha\,\mathcal{H}\big(\pi(\cdot\mid s_t)\big)\right]J(π)=E[t∑​rt​+αH(π(⋅∣st​))]

The entropy bonus makes exploration part of the objective rather than a bolt-on ϵ\epsilonϵ-greedy heuristic, and it produces policies that keep multiple good options alive rather than committing early.

SAC is off-policy, so it reuses data from a replay buffer and is far more sample-efficient than PPO on continuous control. The temperature α\alphaα can be tuned automatically against a target entropy, which removed the method’s main hyperparameter sensitivity. The default choice for continuous control today.

The deadly triad

Section titled “The deadly triad”

Three ingredients that are individually safe and jointly dangerous:

  1. Function approximation — a neural network rather than a lookup table.
  2. Bootstrapping — updating an estimate using another estimate.
  3. Off-policy learning — learning about one policy from data generated by another.

Any two are fine. All three can diverge, provably, on examples as small as two states. And deep RL uses all three: neural nets, TD targets, replay buffers.

Read the standard tricks as triad mitigations

Target networks, replay buffers, gradient clipping, double Q-learning, and conservative penalties are not miscellaneous engineering. They are all attempts to weaken one leg of the triad enough to keep training stable. Knowing that makes the grab-bag look like a coherent response to a single named problem.

∥TQ1−TQ2∥∞≤γ ∥Q1−Q2∥∞.\|\mathcal{T}Q_1 - \mathcal{T}Q_2\|_\infty \leq \gamma\,\|Q_1 - Q_2\|_\infty .∥TQ1​−TQ2​∥∞​≤γ∥Q1​−Q2​∥∞​.

Temporal-difference learning

Section titled “Temporal-difference learning”
Q(st,at)←Q(st,at)+α[rt+γmax⁡aQ(st+1,a)−Q(st,at)]⏟TD error δt.Q(s_t,a_t) \leftarrow Q(s_t,a_t) + \alpha\underbrace{\Big[r_t + \gamma\max_{a}Q(s_{t+1},a) - Q(s_t,a_t)\Big]}_{\text{TD error }\delta_t}.Q(st​,at​)←Q(st​,at​)+αTD error δt​[rt​+γamax​Q(st+1​,a)−Q(st​,at​)]​​.

The TD error is the surprise: how much better or worse things turned out than the current estimate predicted.

What bootstrapping buys and costs. Monte Carlo waits for the episode to end and uses the actual return — unbiased, high variance, and unusable for continuing tasks. TD updates immediately from an estimate — biased (the estimate is wrong early), much lower variance, and usable online. The bias is the price of the variance reduction, and it is the second leg of the triad.

  • A^t<0\hat A_t < 0A^t​<0 (bad action): the penalty is not capped below 1−ε1-\varepsilon1−ε — pushing probability down further is always permitted.

So the objective allows unbounded retreat from bad actions and bounded advance toward good ones, which is the conservative direction when your value estimates might be wrong.

Offline RL and distribution shift

Section titled “Offline RL and distribution shift”

Offline RL learns from a fixed dataset with no environment interaction. The failure mode is specific and severe.

The Bellman target contains max⁡a′Q(s′,a′)\max_{a'}Q(s',a')maxa′​Q(s′,a′). For actions not in the dataset, QQQ is an extrapolation — and because of the max, errors are selected for. The optimiser seeks out exactly the actions whose values are erroneously high, and bootstrapping propagates those errors backwards through the whole value function.

CQL adds a penalty pushing down QQQ on out-of-distribution actions:

LCQL=α(Es∼D, a∼μ[Q(s,a)]−E(s,a)∼D[Q(s,a)])+LTD,\mathcal{L}_{\text{CQL}} = \alpha\Big(\mathbb{E}_{s\sim\mathcal{D},\,a\sim\mu}\big[Q(s,a)\big] - \mathbb{E}_{(s,a)\sim\mathcal{D}}\big[Q(s,a)\big]\Big) + \mathcal{L}_{\text{TD}},LCQL​=α(Es∼D,a∼μ​[Q(s,a)]−E(s,a)∼D​[Q(s,a)])+LTD​,

which lower-bounds the true value, so the policy cannot be fooled by optimistic extrapolation. It is deliberately pessimistic, and pessimism is the correct posture when you cannot test your beliefs.

Decision Transformer sidesteps all of this by reframing RL as sequence modelling: condition on a desired return and predict actions autoregressively. No Bellman equation, no bootstrapping, no triad. It works well on some benchmarks and degrades when the desired return is far outside what the dataset demonstrates — which is exactly the extrapolation problem reappearing in a different costume.

Tier 4 · Frontier

Open problems, current results, and what is still contested.

Where this stands, as of 2026

Section titled “Where this stands, as of 2026”

RL’s largest impact today is on language models, not robots. RLHF, DPO and RLVR are RL applied to text generation, and they are what turned base models into assistants. See post-training — the algorithms there are PPO and its descendants.

Model-based RL is competitive and no longer exotic. DreamerV3 masters a wide range of domains with fixed hyperparameters and was the first system to collect diamonds in Minecraft from scratch. Learning a world model and planning inside it is substantially more sample-efficient than model-free RL — the connection to world models is direct.

Sample efficiency remains the binding constraint for physical systems. Millions of environment steps are fine in simulation and prohibitive on a real robot. This is why sim-to-sim transfer, offline RL from logged data, and world models all attract effort.

Reproducibility is genuinely poor and now acknowledged. Deep RL results vary enormously across random seeds; single-seed comparisons are close to meaningless. Reporting multiple seeds with confidence intervals is now expected, and older results should be read with that in mind.

Open problems

Section titled “Open problems”

  • Exploration in sparse-reward settings is unsolved. When reward is essentially never observed, undirected exploration never finds it. Intrinsic motivation and curiosity help on some benchmarks and generalise poorly.

  • Reward specification is hard and adversarial. Writing a reward that captures what you want, and cannot be satisfied by something you don’t, is the same problem as reward hacking in RLHF. Agents reliably find the degenerate solution.

  • No theory for deep RL. Convergence guarantees are for tabular methods. With function approximation, essentially nothing is proven about the algorithms in actual use.

  • Generalisation is weak. Agents trained on one environment often fail on cosmetic variations. Whether this is an RL problem or a representation problem is unclear.

  • Off-policy evaluation is unreliable. Estimating a new policy’s value from old data — needed for any high-stakes deployment — has high variance and no trustworthy estimator.
